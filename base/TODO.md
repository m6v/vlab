# Управление виртуальными машинами по сети

## Использование «транслятора»

На сервере-хосте (перенаправляем UNIX-сокет на сетевой TCP-порт, например, 4444):
```
socat TCP-LISTEN:4444,fork,reuseaddr UNIX-CONNECT:/tmp/qemu/m6v/arm-abi.sock &
```
>Параметр fork позволит сокету не закрываться после первой же команды, а принимать их постоянно

На удаленном компьютере вместо UNIX-CONNECT используют TCP
```
echo "info block" | socat - TCP:IP_АДРЕС_СЕРВЕРА:4444
```
>Внимание по безопасности: UNIX-сокеты по умолчанию защищены правами доступа Linux (никто, кроме вашего пользователя, не может в них писать). Как только вы транслируете сокет в TCP-порт, любой человек в сети сможет управлять вашей виртуалкой (вплоть до её удаления или изменения дисков).

Чтобы настроить постоянный сетевой TCP-порт для управления виртуальной машиной, лучше всего отказаться от промежуточных утилит вроде socat в фоне и заставить сам QEMU при старте открыть сетевой порт.

Вы можете использовать два протокола передачи команд: HMP (обычные текстовые команды, которые вы использовали) или QMP (профессиональный JSON-интерфейс, используемый virt-manager/libvirt).

## Использование постоянного порта

Для использования постоянного порта HMP (Обычные текстовые команды) нужно изменить строку запуска виртуальной машины. Вместо параметра -monitor unix: указать сетевой адрес и порт:
```
# Было: -monitor unix:/tmp/qemu/$USER/$VM_NAME.sock,server,nowait
# Стало:
-monitor tcp:0.0.0.0:4444,server,nowait
```

• 0.0.0.0 означает, что QEMU будет слушать команды со всех сетевых интерфейсов хоста (включая внешнюю сеть). Если вам нужно управлять только в пределах хоста, напишите 127.0.0.1.
• 4444 — номер TCP-порта.

Теперь с любого компьютера в сети (или с самого хоста) вместо UNIX-CONNECT используют сетевое подключение по TCP:

```
# Подключение диска удаленно:
echo "drive_add 0 if=none,id=${DISK_ID},file=${DISK_PATH},format=raw" | socat - TCP:IP_АДРЕС_СЕРВЕРА:4444
echo "device_add usb-storage,drive=${DISK_ID},id=${DISK_ID},bus=usb3.0" | socat - TCP:IP_АДРЕС_СЕРВЕРА:4444

# Отключение диска удаленно:
echo "device_del ${DISK_ID}" | socat - TCP:IP_АДРЕС_СЕРВЕРА:4444
echo "drive_del ${DISK_ID}" | socat - TCP:IP_АДРЕС_СЕРВЕРА:4444
```
>Интерфейс управления QEMU не имеет встроенной авторизации, логинов или паролей. Любой человек в вашей сети, который сможет достучаться до порта 4444, получит полный контроль над вашей виртуальной машиной (сможет её выключить, удалить диски или выполнить произвольный код).

Для каждой виртуальной машины нужен свой уникальный TCP-порт (например, 4444, 4445, 4446).
